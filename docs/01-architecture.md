# المعمارية الشاملة لنظام CRM العقاري (Dual-Pipeline Architecture)

## 1. فلسفة النظام وأهدافه
صُمم هذا النظام خصيصاً لشركات ووكالات الوساطة والتسويق العقاري ليعالج نقطة الضعف الشائعة في أنظمة الـ CRM التقليدية، وهي خلط طلبات الإيجار بصفقات الريسيل.

* **العميل هو نقطة الارتكاز (Customer-Centric):** العميل (سواء كان مشترياً، مستأجراً، مالكاً، أو مستثمراً) يمتلك سجلاً واحداً مركزياً يحتوي على كافة أرقام هواتفه، بريده، وسجل تواصله، لمنع التكرار وضمان عدم تشتت المتابعات بين الموظفين.
* **مساران تشغيليان منفصلان (Dual Operational Pipelines):**
  1. **مسار الإيجارات (Rental Pipeline):** يركز على سرعة دورة المعاملة، شروط السكن والتأثيث، الميزانية الشهرية/السنوية، تاريخ الانتقال، وترشيح ومعاينة الوحدات المتاحة للإيجار.
  2. **مسار الريسيل (Resale Pipeline):** يركز على القدرة التمويلية، أنظمة السداد (كاش / تقسيط)، المقدم والأقساط وتاريخ الاستلام، وترشيح ومعاينة مشروعات ووحدات إعادة البيع.

## 2. الهيكل المعماري للنظام (System Architecture)

```text
                               +-----------------------------+
                               |     المستخدمين والصلاحيات    |
                               | (مدير / إيجارات / ريسيل)   |
                               +--------------+--------------+
                                              |
                     +------------------------v------------------------+
                     |         قاعدة البيانات المشتركة (Shared Core)   |
                     |  - العملاء (Clients) مع كشف تكرار الهواتف      |
                     |  - الوسطاء والشركاء (Brokers)                   |
                     |  - سجل الأنشطة والاتصالات (Activity Timeline)   |
                     |  - المتابعات والتذكيرات (Follow-ups)            |
                     +------------+-----------------------+------------+
                                  |                       |
            +---------------------v-------+       +-------v---------------------+
            |     قسم الإيجارات (Rentals) |       |      قسم الريسيل (Resale)   |
            +-----------------------------+       +-----------------------------+
            | 1. طلبات الإيجار             |       | 1. طلبات الريسيل            |
            | 2. المتطلبات والميزانية     |       | 2. متطلبات الشراء والتقسيط   |
            | 3. ترشيحات وحدات الإيجار    |       | 3. ترشيحات وحدات الريسيل    |
            | 4. فحص الوحدات              |       | 4. فحص الوحدات والجاهزية    |
            | 5. معاينات المستأجرين       |       | 5. معاينات المشترين         |
            | 6. إغلاق صفقات الإيجار      |       | 6. إغلاق صفقات البيع والعمولة|
            +-----------------------------+       +-----------------------------+
```

## 3. الأدوار والصلاحيات (Role-Based Access Control)

| الدور | نطاق الوصول والصلاحيات |
| :--- | :--- |
| **المدير (Super Admin / Manager)** | وصول كامل لكافة العملاء والطلبات والإحصائيات، تقارير الأداء، وسجل التدقيق وإعدادات النظام. |
| **موظف الإيجارات (Rental Agent)** | وصول تشغيلي لإنشاء العملاء وإدارة طلبات الإيجار وترشيح وفحص ومعاينة وحدات الإيجار وإغلاق صفقاتها. لا يرى طلبات قسم الريسيل لحفظ التركيز. |
| **موظف الريسيل (Resale Agent)** | وصول تشغيلي لإنشاء العملاء وإدارة طلبات الريسيل وتفاصيل الأقساط والمعاينات وإغلاق صفقات البيع. لا يرى طلبات قسم الإيجار. |

## 4. المكونات التشغيلية الذكية (Smart Subsystems)

1. **كشف تكرار العملاء (Phone Deduplication Engine):**
   * يتم تنظيف رقم الهاتف داخلياً واستخراج الأرقام فقط وتوحيد الصيغة الدولية (`normalized_phone`).
   * عند إدخال الهاتف في أي نموذج، يظهر إشعار فوري في حال وجود عميل مسجل بنفس الرقم لتفادي الازدواجية، مع إتاحة إضافة طلب جديد لنفس العميل بضغطة زر.
2. **صمام أمان المعاينات (Inspection Gatekeeper Rule):**
   * لحماية وقت الفريق والعميل، يمنع النظام برمجياً جدولة أي "معاينة عميل" لوحدة ما لم يكن أحدث فحص مسجل لها بنتيجة **(مناسبة)**.
3. **فصل الميزانية المذكورة عن المؤهلة (Budget Qualification):**
   * تسجيل ما ذكره العميل مبدئياً (`stated_budget`).
   * تسجيل ما ثبتت جاهزيته لدفعه بعد مناقشة السوق (`qualified_budget`) بدون مسح القيمة الأصلية.
