# دليل تطبيق سيبل العقارية لإدارة عمليات الإيجار

## نبذة عن التطبيق

**سيبل العقارية لإدارة عمليات الإيجار** هو نظام داخلي لإدارة رحلة عميل الإيجار من أول تواصل حتى إغلاق الصفقة، مع الاحتفاظ بسجل عملي واضح لكل ما حدث على الطلب.

يركّز التطبيق على عمل فريق الإيجارات اليومي: العملاء، متطلبات الإيجار، ترشيح الوحدات، الفحص، المعاينات، التواصل، المتابعات، وإغلاق الصفقات.

> التطبيق ليس نظام إدارة أملاك أو حسابات أو عقود. كما أنه مستقل تمامًا عن أي نظام خارجي للوحدات أو العقارات.

## ما الذي يديره التطبيق؟

```text
عميل
  ↓
طلب إيجار مستقل
  ↓
متطلبات وميزانية
  ↓
وحدات مُرشحة
  ↓
فحص الوحدة
  ↓
معاينة العميل
  ↓
أنشطة ومتابعات وتفاوض
  ↓
صفقة ناجحة أو غير ناجحة
```

هذه الرحلة مرنة وليست مسارًا إجباريًا. يمكن للموظف تعديل المتطلبات، إرسال أكثر من وحدة، إجراء أكثر من فحص أو معاينة، أو جدولة متابعة جديدة حسب تطور الحالة.

## الأدوار والصلاحيات

يوجد في النظام دوران فقط:

| الدور | الاستخدام |
| --- | --- |
| **مدير** | وصول كامل إلى بيانات وتشغيل CRM، بما في ذلك جميع العملاء والطلبات والمتابعات والمعاينات والنتائج. |
| **موظف إيجارات** | وصول تشغيلي لإنشاء وإدارة العملاء وطلبات الإيجار والتواصل والمتابعات والوحدات والفحوصات والمعاينات والإغلاق. |

لا توجد حسابات أو أدوار مستقلة للوكلاء أو السكرتارية أو الوسطاء أو ملاك العقارات. الموظف أو المدير المسجل دخوله هو المسؤول الذي يسجل النشاط أو الفحص أو المعاينة عند الحاجة.

لا يستطيع المستخدم غير النشط الوصول إلى النظام حتى لو كان لديه حساب صحيح.

## الوحدات الرئيسية

### 1. تسجيل الدخول

- تسجيل دخول آمن للمستخدمين المعتمدين.
- تخزين كلمات المرور بصورة مشفرة.
- حماية النماذج من CSRF وإعادة إنشاء الجلسة بعد تسجيل الدخول.
- تسجيل خروج آمن.

### 2. لوحة الرئيسية

تعرض ملخصًا سريعًا للنتائج التشغيلية المسجلة، منها:

- عدد الصفقات المغلقة بنجاح.
- عدد الصفقات المغلقة دون نجاح.
- وصول سريع إلى العملاء وطلبات الإيجار والمتابعات.

### 3. العملاء

يمثل العميل الشخص أو الجهة ذات بيانات الاتصال المستقرة، وليس طلب الإيجار نفسه.

#### البيانات المسجلة

- الاسم الكامل.
- رقم الهاتف كما أدخله الموظف.
- رقم هاتف موحّد داخليًا للبحث واكتشاف التكرار.
- البريد الإلكتروني عند توفره.
- الجنسية.
- ملاحظات عامة.
- من أنشأ أو حدّث السجل وتواريخه.

#### ما يستطيع الموظف فعله

- عرض قائمة العملاء مع البحث بالاسم أو الهاتف.
- إنشاء ملف عميل وتعديله وعرضه.
- الاطلاع على عدد طلبات الإيجار وآخر طلب وآخر نشاط من البيانات المرتبطة، بدون تكرار هذه المعلومات داخل سجل العميل.
- فتح ملف العميل للاطلاع على طلباته وأنشطته الأخيرة.
- إنشاء طلب إيجار جديد من داخل ملف العميل.

#### منع تكرار العميل

عند إدخال رقم هاتف، يُطبع الرقم لاكتشاف التطابقات المحتملة. إذا وُجد عميل بالرقم نفسه، يظهر تحذير واضح للموظف بدل دمج السجلين تلقائيًا. يبقى قرار المتابعة أو الرجوع للموظف.

#### طلب عبر وسيط دون عميل معروف

يمكن إنشاء طلب إيجار مرتبط بوسيط من دون اختيار عميل. لا يُسجل الوسيط كعميل بديل ولا يُنشأ عميل وهمي. للوسيط سجل مستقل قابل لإعادة الاستخدام في طلبات متعددة، ويمكن ربط عميل حقيقي بالطلب لاحقًا عند توفر بياناته. رقم العميل أو الوسيط الداخلي هو رقم السجل الحالي (#ID) ويظهر في ملفات البحث والاختيار.

### 4. طلبات الإيجار

طلب الإيجار هو السجل التشغيلي المركزي، وهو منفصل تمامًا عن العميل.

- يمكن للعميل الواحد امتلاك عدة طلبات حالية أو تاريخية.
- إغلاق طلب لا يؤثر في بقية طلبات العميل.
- يمكن إنشاء الطلب من ملف العميل أو من شاشة طلبات الإيجار بعد البحث عن عميل قائم.

#### معلومات الطلب

- العميل المرتبط بالطلب.
- مصدر الطلب كنص حر، مثل: فيسبوك أو واتساب الشركة أو إحالة صديق.
- طريقة التواصل.
- عدد الأشخاص وحالة الأسرة.
- الموظف المسؤول.
- حالة تشغيلية للطلب.
- ملاحظات عامة.

#### حالات الطلب

الحالة مؤشر تشغيلي مرن وليست آلة انتقالات جامدة. يدعم التطبيق حالات مثل:

`جديد`، `نشط`، `تم التواصل`، `تم تأكيد المتطلبات`، `جارٍ البحث`، `تم إرسال الخيارات`، `أبدى اهتمامًا`، `تمت جدولة المعاينة`، `اكتملت المعاينة`، `قيد التفاوض`، `معلّق`، `مغلق بنجاح`، `مغلق دون نجاح`.

#### البحث والتصفية

يمكن البحث أو التصفية في قائمة الطلبات حسب:

- اسم العميل أو رقم هاتفه.
- مصدر الطلب.
- الحالة.
- الموظف المسؤول.
- فترة الإيجار.
- الموقع المفضّل.

### 5. متطلبات الإيجار والميزانية

لكل طلب بيانات متطلبات وبيانات ميزانية مستقلة عن ملف العميل.

#### المتطلبات

- نوع العقار وغرف النوم.
- فترة الإيجار والمدة المطلوبة.
- تاريخ الانتقال المطلوب.
- مستوى التشطيب.
- المواقع والمشروعات أو الكمباوندات المفضلة كنص مرن.
- متطلبات إضافية، مثل الدور أو المصعد أو الإطلالة أو الموقف أو الأثاث.

#### الميزانية

يفصل التطبيق بين مفهومين مهمين:

1. **ميزانية العميل المذكورة:** ما صرّح به العميل مبدئيًا.
2. **الميزانية المؤهلة أو الواقعية:** ما أصبح العميل مستعدًا لدفعه بعد مناقشة السوق.

يمكن حفظ الحد الأدنى والأقصى لكل منهما، العملة، حالة تأهيل الميزانية، وملاحظات النقاش. لا يتم استبدال الميزانية المذكورة بالميزانية المؤهلة.

### 6. الأنشطة وسجل التواصل

الأنشطة هي سجل زمني للأمور التي حدثت بالفعل على طلب الإيجار.

#### أمثلة للأنشطة

- مكالمة هاتفية.
- واتساب أو رسالة أو بريد إلكتروني.
- اجتماع أو ملاحظة.
- رد العميل.
- إرسال وحدة.
- تسجيل فحص أو معاينة أو إغلاق صفقة تلقائيًا كسجل تشغيلي موجز.

كل نشاط يحتوي على النوع والوصف والنتيجة عند توفرها وتاريخ/وقت الحدوث والموظف الذي سجله. تظهر الأنشطة في صفحة الطلب بترتيب زمني حديث أولًا.

الأنشطة التاريخية لا تُحرر أو تُحذف من الواجهة التشغيلية المعتادة؛ التصحيح يتم بإضافة نشاط جديد يشرح التصحيح.

### 7. المتابعات

المتابعة عمل مطلوب في المستقبل، وليست نشاطًا حدث بالفعل.

#### بيانات المتابعة

- الموظف المسؤول.
- تاريخ ووقت الاستحقاق.
- الإجراء المطلوب.
- ملاحظات.
- الحالة: معلّقة أو مكتملة أو ملغاة.
- من أنشأها ومن أكملها ووقت الإكمال والنتيجة.

#### طريقة العمل

- المتابعة المعلّقة التي تجاوز موعدها تعتبر متأخرة تلقائيًا؛ لا توجد حالة متأخرة مكررة في قاعدة البيانات.
- يمكن إكمال المتابعة مع إضافة نشاط اختياري يشرح ما حدث.
- يمكن إلغاء المتابعة المعلّقة عند عدم الحاجة إليها.
- شاشة المتابعات تعرض اليوم والمتأخر والقادم والمكتمل والملغى، مع تصفية بالموظف المسؤول.
- تاريخ النشاط والمتابعة هما مصدر الحقيقة؛ لا يوجد حقل مكرر مثل "المتابعة الحالية" داخل طلب الإيجار.

### 8. ترشيحات الوحدات

ترشيح الوحدة هو لقطة تاريخية لما تم عرضه أو إرساله للعميل، وليس سجلاً رئيسيًا للعقارات.

#### البيانات الممكن حفظها

- كود وحدة اختياري رقمي فقط.
- مرجع أو عنوان الوحدة.
- اسم العقار والمشروع أو الكمباوند والموقع.
- النوع وعدد الغرف وفترة الإيجار والتشطيب.
- الإيجار المطلوب والعملة.
- رابط صور أو مرجع خارجي عند توفره.
- تاريخ الإرسال والموظف الذي سجله.
- رد العميل وحالة اهتمامه وملاحظات الموظف.

يمكن إضافة عدد غير محدود عمليًا من الترشيحات إلى الطلب، مع تحديث الردود والملاحظات دون حذف السجل التاريخي. عند إنشاء الترشيح، يسجل النظام نشاطًا من نوع "إرسال وحدة" ويضيف حدثًا إلى سجل التدقيق.

> `unit_code` مجرد مرجع اختياري يُدخل يدويًا. لا توجد أي API أو اتصال قاعدة بيانات أو تحقق خارجي أو مزامنة مرتبطة به.

### 9. فحص الوحدة

الفحص مرتبط بترشيح وحدة محدد، ويمكن تسجيل أكثر من فحص للوحدة نفسها بمرور الوقت.

#### ما يتم تسجيله

- وقت الفحص والموظف الذي قام به.
- النتيجة النهائية: مناسبة أو غير مناسبة.
- مدى توافر الوحدة.
- تطابق الصور أو المعلومات مع الواقع.
- النظافة وحالة الأثاث والمرافق.
- العيوب أو الملاحظات الظاهرة.
- سبب عدم المناسبة، وهو إلزامي عند اختيار "غير مناسبة".

تظل جميع الفحوصات التاريخية مرئية. أحدث فحص هو الذي يحدد أهلية الوحدة لجدولة معاينة العميل. عند تسجيل فحص، ينشئ النظام نشاطًا موجزًا وسجل تدقيق.

### 10. معاينات العملاء

المعاينة مرتبطة بطلب إيجار محدد وترشيح وحدة محدد، ويمكن أن توجد عدة معاينات للوحدة أو للطلب نفسه.

#### قاعدة الحماية الأساسية

لا يمكن جدولة معاينة إلا إذا كان **أحدث فحص** للوحدة مناسبًا. إذا لم يوجد فحص أو كانت نتيجة أحدث فحص غير مناسبة، يمنع النظام الجدولة.

#### بيانات المعاينة

- موعد المعاينة والموظف المسؤول.
- حالة المعاينة، مثل: مجدولة، مؤكدة، مكتملة، عدم حضور العميل، ملغاة، أو معاد جدولتها.
- استجابة العميل عند اكتمالها.
- ملاحظات العميل واعتراضاته وملاحظات الموظف.

توجد شاشة عامة للمعاينات تدعم البحث باسم العميل أو هاتفه والتصفية بالتاريخ والحالة والموظف. ينتج عن الجدولة أو تغيّر الحالة نشاط موجز، ولا يكرر النظام النشاط عند مجرد فتح السجل أو عرضه.

### 11. إغلاق الصفقة ونتيجتها

لكل طلب نتيجة نهائية واحدة فقط: **ناجحة** أو **غير ناجحة**.

#### صفقة ناجحة

عند إغلاق الطلب بنجاح، يسجل التطبيق:

- ترشيح الوحدة التي تم تأجيرها، ويجب أن ينتمي إلى الطلب نفسه.
- الإيجار النهائي والعملة وفترة الإيجار.
- الموظف المسؤول ومن أغلق السجل.
- تاريخ الإغلاق والملاحظات.
- بيانات الوسيط والعمولة عند وجود وسيط.

#### صفقة غير ناجحة

عند الإغلاق دون نجاح، يكون سبب الخسارة مطلوبًا، مع إمكانية إضافة ملاحظات. تشمل الأسباب الشائعة الميزانية أو الموقع أو السعر أو عدم مناسبة الوحدة أو توقف العميل عن الرد أو تأجيله.

#### أثر الإغلاق

- تتحول حالة الطلب تلقائيًا إلى مغلق بنجاح أو مغلق دون نجاح.
- يسجل النظام نشاط إغلاق وسجل تدقيق.
- لا يمكن إضافة أعمال تشغيلية جديدة مثل ترشيح وحدة أو فحص أو معاينة أو متابعة أو نشاط عادي إلى الطلب المغلق.
- يسمح بتعديل تفاصيل نتيجة الإغلاق مع الحفاظ على نوع النتيجة نفسه وسجل التدقيق.

### 12. الوسطاء والعمولة

يمكن ربط صفقة ناجحة بوسيط عند الحاجة، مع حفظ اسم الوسيط وهاتفه ضمن سجل الوسطاء، ثم تسجيل معلومات العمولة المتفق عليها على نتيجة الصفقة.

العمولة مرنة: مبلغ وعملة وملاحظات. لا يطبق التطبيق أي معادلة عمولة ثابتة أو نظام محاسبة.

## العلاقات الأساسية بين البيانات

```text
مستخدم
 ├── ينشئ ويحدّث العملاء والطلبات
 ├── يسجل الأنشطة والمتابعات والفحوصات والمعاينات
 └── يسجل أحداث التدقيق

عميل
 └── طلب إيجار واحد أو أكثر
      ├── متطلبات إيجار واحدة
      ├── ميزانية واحدة
      ├── أنشطة متعددة
      ├── متابعات متعددة
      ├── ترشيحات وحدات متعددة
      │    ├── فحوصات متعددة
      │    └── معاينات متعددة
      └── نتيجة صفقة واحدة كحد أقصى
```

## سجل التدقيق والموثوقية

يسجل النظام الأحداث التشغيلية المهمة، مثل إنشاء أو تحديث ترشيح وحدة، إنشاء فحص، إنشاء أو تغيير معاينة، إنشاء أو إكمال أو إلغاء متابعة، وإنشاء أو تحديث نتيجة صفقة.

يحفظ سجل التدقيق المستخدم المنفذ، نوع الحدث، القيم القديمة والجديدة عند الحاجة، عنوان IP، ومتصفح المستخدم. وهو منفصل عن النشاط التشغيلي المعروض للفريق.

تستخدم السجلات الرئيسية الحذف الناعم حيث ينطبق ذلك، لحماية التاريخ التشغيلي من الفقد غير المقصود.

## حدود التطبيق الحالية

التطبيق لا ينفذ ولا يهدف إلى تنفيذ ما يلي:

- إدارة مخزون عقاري أو قاعدة بيانات رئيسية للوحدات.
- اتصال أو مزامنة مع نظام العقارات الخارجي.
- تحصيل الإيجارات أو المحاسبة أو حساب عمولات تلقائي.
- إدارة عقود أو صيانة أو أوامر عمل أو ملاك عقارات.
- حسابات وكلاء أو وسطاء أو مستخدمين خارجيين.
- تكامل WhatsApp أو البريد الإلكتروني أو إشعارات تلقائية.
- نظام تقارير وذكاء أعمال متقدم.

## شاشات التنقل

| الشاشة | الغرض |
| --- | --- |
| الرئيسية | ملخص الصفقات والوصول السريع. |
| العملاء | البحث عن العملاء وإنشاؤهم وتعديلهم وفتح ملفاتهم. |
| طلبات الإيجار | إدارة قائمة الطلبات والبحث والتصفية وإنشاء طلب جديد. |
| صفحة تفاصيل الطلب | المركز التشغيلي للمتطلبات والميزانية والوحدات والفحوصات والمعاينات والأنشطة والمتابعات والنتيجة. |
| المتابعات | قائمة العمل اليومي والمتأخر والقادم وسجل المتابعات. |
| معاينات العملاء | عرض المعاينات والتصفية وتحديث حالتها. |
| نتائج الصفقات | البحث في الصفقات المغلقة الناجحة وغير الناجحة ومراجعة بياناتها. |

## متطلبات التشغيل المحلية

- Laravel 12.
- PHP 8.2 أو أحدث متوافق.
- MySQL من خلال XAMPP أو بيئة متوافقة.
- جلسات ملفات محلية في الإعداد الحالي.

بعد تجهيز بيانات الاتصال بقاعدة البيانات داخل `.env`:

```powershell
php artisan config:clear
php artisan migrate
php artisan rental:create-manager
```

عنوان التشغيل المحلي الحالي:

```text
http://localhost/ciblecrm/public
```
